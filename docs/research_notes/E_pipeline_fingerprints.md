# E. Pipeline fingerprints: what open-source auto-research pipelines leave in the papers they produce

Research date: 2026-10-05. Every repo below was cloned and read directly (`git clone --depth 1`; ARIS was un-shallowed so its prompt history could be read). Quotes are verbatim from the files named. The commit hash at clone time is given for each repo so links can be pinned.

**Method.** If a paper was produced end-to-end by a pipeline, the pipeline's prompts, templates, compute caps and review loops shape the paper in ways a reviewer can see. For each pipeline I read the writing prompts, the idea/experiment/review prompts and the hard-coded constants, then wrote down what each would produce in the final PDF or LaTeX source. Strength ratings (used in the catalog at the end):

- **S (strong):** close to unique to the pipeline, or a literal watermark or source artifact. One hit is meaningful.
- **M (moderate):** a recognisable habit that some human papers also show. Needs 2-3 co-occurring signals.
- **W (weak):** common in ordinary ML writing. Only useful as part of a cluster.

Caveat: most fingerprints only show that a pipeline was used. They do not prove the work was unsteered "slop". Fingerprints become slop evidence when they co-occur with research-level signals: toy scale, a failed pivot, phantom experiments, claims that contradict the figures, or a reviewer-optimised structure with no substance behind it.

## 1. ARIS: Auto-claude-code-Research-In-Sleep (wanshuiyin)

- Repo: https://github.com/wanshuiyin/Auto-claude-code-research-in-sleep (HEAD `2132036`, 2026-09-29). It is very active: 1,215 commits since 2026-03-10, about 79 bundled skills, a technical report at arXiv 2605.03042, a VALSE 2026 talk, and coverage on PaperWeekly. It is big in the Chinese community; many skill triggers are Chinese ("写论文", "找idea全流程", "改论文").
- Architecture: Claude Code (or Codex, Cursor, Trae, Copilot) is the executor. A cross-family reviewer (GPT "gpt-5.4" → "gpt-5.5" → "gpt-5.6-sol" → "gpt-6-astra" at xhigh effort) is called through Codex MCP. Workflows: `/idea-discovery` (W1) → `/experiment-bridge` → `/auto-review-loop` (W2) → `/paper-writing` (W3: paper-plan → paper-figure → paper-write → paper-compile → auto-paper-improvement-loop) → `/rebuttal` (W4). `/research-pipeline` chains all of them "overnight".

### 1.1 Research process and constraints

| Constraint | Source (file, quote) | Effect on paper |
|---|---|---|
| Tiny pilot budget | `skills/idea-discovery/SKILL.md`: "**PILOT_MAX_HOURS = 2** — Skip any pilot experiment estimated to take > 2 hours per GPU", "**MAX_PILOT_IDEAS = 3**", "**MAX_TOTAL_GPU_HOURS = 8** — Total GPU budget across all pilots." | Ideas are chosen for what pays off fast and cheap. The project survives only if a ≤2 GPU-h pilot shows a signal, so expect small models, short training and quick-signal metrics. |
| Idea gate = novelty search + pilot | `idea-discovery`: "/research-lit → /idea-creator → /novelty-check → /research-review → /research-refine-pipeline"; "Multi-source literature search (arXiv, Scholar, Semantic Scholar)"; "Let pilots kill, not vibes." Since 2026-08-26: "ABANDON now has to name the published paper that already contains your result" (README changelog). | Ideas sit in narrow gaps near recent arXiv work. Related work is skewed to recent arXiv preprints found by search. |
| Seeds and baselines | `skills/experiment-plan/SKILL.md`: "**DEFAULT_SEEDS = 3** — Use 3 seeds when stochastic variance matters and budget allows."; "**MAX_BASELINE_FAMILIES = 3** — Prefer a few strong baselines over many weak ones."; "Design the main table first, then add only the ablations that defend it." | Exactly 3 seeds (often seed 42 first; `experiment-bridge` shows `--seed 42`). At most 3 baseline families. The ablations exist to defend the main table. |
| Auto-review loop optimises the reviewer's score | `skills/auto-review-loop/SKILL.md` (present since the first version, 2026-03-10, commit `7db48e0`): "MAX_ROUNDS = 4"; "POSITIVE_THRESHOLD: score >= 6/10 **AND** verdict ∈ {"ready", "almost"}"; reviewer prompt: "Score this work 1-10 for a top venue … For each weakness, specify the MINIMUM fix (experiment, analysis, or reframing) … Be brutally honest."; "HUMAN_CHECKPOINT = false … When `false` (default), the loop runs fully autonomously." | The paper is shaped to get an LLM reviewer to 6/10. Each critique gets a minimal patch, usually a reframing, so the result reads as reviewer-proofed. |
| Reframing is preferred to new experiments | `auto-review-loop`, Phase C prioritisation rules: "Skip fixes requiring excessive compute (flag for manual follow-up)"; "**Prefer reframing/analysis over new experiments when both address the concern**"; "Always implement metric additions (cheap, high impact)". | When a claim fails, the cheapest move is to change the story, not run the experiment. Expect many metrics, "analysis" sections standing in for missing experiments, and a scope that narrows over the rounds. |
| The repo's own "real run" shows the pivot to a diagnostic paper | `README.md` §5 "Score Progression (Real Run)": "Round 1 6.5/10: Added standard metrics, discovered metric decoupling; Round 2 6.8/10: Key claim failed to reproduce, pivoted narrative; Round 3 7.0/10: Large seed study killed main improvement claim; Round 4 **7.5/10** ✅: Diagnostic evidence solidified, **submission ready**". | **Key fingerprint.** The method claim dies, and the same paper is relabelled a "diagnostic", "analysis" or "metric decoupling" study, then submitted. Look for a method-paper skeleton (a proposed component, ablation tables) wearing a diagnostic title or abstract. |
| Honesty mandate in the loop | `auto-review-loop`: "Be honest — include negative results and failed experiments"; "Do NOT hide weaknesses to game a positive score"; "**Exhaust before surrendering** … (3) for theory issues, provide a weaker version of the result … (4) only then concede narrowly and bound the damage." | Negative results and narrowed claims stay in the paper. "Weaker version of the result" plus "bound the damage" yields claims qualified by many conditions. |
| Result-to-claim gate | `skills/result-to-claim/SKILL.md`: "suggested_claim_revision: if the claim should be strengthened, weakened, or reframed"; "Multiple rounds of `partial` on the same claim → … consider whether to narrow the claim scope or switch ideas"; "A single positive result on one dataset does not support a general claim. Be honest about scope." | Claims scoped to "in our setting" or "on X". Claims-Evidence Matrix language. |
| Stall detection forces pivots | `skills/research-pipeline/SKILL.md`: "Overnight heartbeat: stall detection → forced structural pivot … on `pivot=structural` (stale ≥ 2) the nudge must change a STRUCTURAL constraint and pick an untried direction". | When the agent stalls overnight it changes direction. The final paper can mix two half-finished directions. |
| Integrity audits name the failure modes the authors have actually seen | `skills/experiment-audit/SKILL.md`: "check for fake ground truth, score normalization fraud, phantom results, and insufficient scope". | The maintainers know these failure modes occur, so treat them as things to check for in suspect papers. |

### 1.2 Writing prompts, in two eras (the history is itself evidence)

**Era A, 2026-03-13 to 2026-08-25 (most ARIS papers submitted to ICLR/ICML/AAAI/NeurIPS 2026 cycles).** These lines come from the parent of commit `e9e51ff`:

- `skills/paper-write/SKILL.md`: "Limitations (be honest — reviewers appreciate this)"; "**No over-claiming** — use hedging language ("suggests", "indicates") for weak evidence".
- `skills/auto-paper-improvement-loop/SKILL.md` fix table: "| Overclaims | Soften language: "validate" → "demonstrate practical relevance", "comparable" → "qualitatively competitive" |"; Round 2 instructions: "Further soften any remaining overclaims", "Strengthen limitations section"; key rule: "**Global consistency** — when renaming notation or softening claims, check ALL files (abstract, intro, method, experiments, theory sections, conclusion, tables, figure captions)".
- README benchmark of the improvement loop on an ICLR 2026 theory paper: "Round 1: Fixed assumptions, softened claims, renamed notation"; "Round 2: Added synthetic validation, stronger limitations"; Round-1 fix "Softened "validate" → "demonstrate practical relevance" and added explicit disclaimer".

**The maintainers' own diagnosis.** Commit `e9e51ff` (2026-08-26, PR #423), titled "papers stop reading like confessions", says:
> "Community reports, independent users: ARIS papers read like 忏悔书 — confession letters. Every bad thing admitted one by one throughout the text; telling the model not to mention X produces "we do not address X" in the manuscript; "further research is needed" scattered per paragraph; and no story. … The improvement loops offered exactly one claim-tone operation — soften — with a Round-2 ratchet ("FURTHER soften any remaining overclaims" …) and an amplifier ("when softening claims, check ALL files") that a literal executor reads as copy-the-caution-everywhere. The reviewer rounds did the rest: every criticism absorbed as a new hedge at the point of criticism."

→ **Era-A fingerprints:** caveats spread through every section; "we do not claim / we do not address X" sentences, which expose the drafting instructions; "further research is needed" and "should be interpreted with caution" outside the Limitations section; odd softened verbs ("demonstrate practical relevance", "qualitatively competitive"); an "explicit disclaimer" next to the theory-practice gap; a long Limitations section; and caveats placed exactly where a reviewer would have raised the point. That last one is a direct trace of the reviewer loop.

**Era B, 2026-08-26 onward (current HEAD).** The "CONFIDENT PROSE, HONEST LIMITS" contract in `paper-write/SKILL.md` was added, followed by the 2026-09-03 "press-release principle" (rules 9-12, adopted from github.com/Adkid-Zephyr/anti-defensive-writing-Skill):
- "Put generic caveats … in one Limitations section"; "Aim for 2-4 material, specific limitations (dataset scale, compute regime, assumption X)".
- "Pick the contest the paper wins. Do not build the narrative on a metric where the method is not ahead; frame the comparison around the task definition, evaluation dimension or constraint that reflects what the method is for … explain them as a goal difference or a deliberate tradeoff rather than narrating a defeat ("underperforms", "fails to surpass")".
- "If the results cannot carry the original story, rebuild the story around the strongest evidence instead of defending the original one."
- "Order results by argument, not by lab notebook"; "never narrate the drafting or revision process".

→ **Era-B fingerprints:** a Limitations block of exactly 2-4 items naming "dataset scale / compute regime / assumption X". Losses on standard metrics are explained as "a deliberate tradeoff" or a "different goal". The narrative is built around an unusual evaluation axis or constraint where the method wins. The story is rebuilt after the fact around whatever worked.

**Stable across both eras** (`paper-write/SKILL.md`, `shared-references/writing-principles.md`, adapted from Orchestra):
- Abstract: "Use the 5-part flow … what, why hard, how, evidence, strongest result"; "Include one concrete quantitative result"; "150-250 words". This is Farquhar's five-sentence formula.
- Introduction: "State the gap clearly ("However, ...")"; "List 2-4 specific, falsifiable contributions as a numbered or bulleted list"; "End with a brief roadmap ("The rest of this paper is organized as...")"; "Include the main result figure"; plus a "Hero figure" in `paper-plan`.
- Related Work: "**MINIMUM 1 full page** (3-4 substantive paragraphs)"; "Organize by category using `\paragraph{Category Name.}`"; "End each paragraph with how this paper relates/differs". → A full page of related work organised under bold `\paragraph{…}` headers, each ending with a "Unlike these works, we …" sentence.
- Paper-type templates (`paper-plan`): "**Empirical/Diagnostic paper:** 1. Introduction (1.5 pages) 2. Related Work (1 page) 3. Method / Setup (1.5 pages) 4. Experiments (3 pages) 5. Analysis / Discussion (1 page) 6. Conclusion (0.5 pages)". The Conclusion bundles Limitations and Future work ("Future work (1-2 concrete directions)").
- A Claims-Evidence Matrix drives the outline: "Every claim from the introduction must have supporting evidence here"; "For each major experiment, make explicit what claim it supports and what the reader should notice". Experiments paragraphs therefore open with lines like "This experiment tests Claim 2 …".
- AI-ism deletion list: "Remove AI-isms: delve, pivotal, landscape, tapestry, underscore, noteworthy, intriguingly." → ARIS papers will lack these words. Their absence says nothing; lexicon-based detectors will miss these papers.
- Bibliography: `DBLP_BIBTEX = true` fetches BibTeX from DBLP/CrossRef, and citation keys are standardised to "`{firstauthor}{year}{keyword}` (e.g., `ho2020denoising`)". The .bib contains only cited entries. → Few hallucinated references, DBLP-style entries (`conf/nips/...`, DBLP author disambiguation suffixes like "0001"), and possibly a leftover `% [VERIFY]` comment in the source.
- Figures (`skills/paper-figure/SKILL.md`): "COLOR_PALETTE = `tab10` — Default matplotlib color cycle", "'font.family': 'serif', 'font.serif': ['Times New Roman', …]", "DPI = 300". Architecture figures come from `paper-illustration` ("Generate publication-quality AI illustrations … using Gemini image generation", "gemini-3-pro") or `paper-illustration-image2`. → matplotlib in tab10 colours with serif fonts, plus a glossy AI-generated method diagram.
- Theory papers: Step 3.5 warns that the default "generated `"see supplementary proof document"` placeholders in the appendix". → Look for missing full proofs, or proofs whose appendix restatements drift from the main-text theorems.
- HTML-comment placeholders: "`<!-- DATA_NEEDED: GAP_S5_ABLATION — … -->`", meant to be "invisible in the rendered PDF" and therefore visible in the arXiv LaTeX source.
- `skills/paper-write/SKILL.md` default `TARGET_VENUE = ICLR`, `MAX_PAGES = 9`, `\usepackage{iclr2026_conference,times}`. The real ARIS showcase papers are an AAAI 2026 submission, an IEEE TGRS submission (UAV-CC) and an unnamed CS conference.
- Example narrative (`docs/NARRATIVE_REPORT_EXAMPLE.md`): "We propose **Adaptive Sparsity Distillation (ASD)**"; proposed title "Attention Sparsity Scales with Context: Distilling Adaptive Sparse Masks for Long-Range Transformers". This is the expected template: a two-part "Finding: Method" title with an adjective-noun-noun acronym.

### 1.3 Self-reported AI-review scores as a fingerprint
In its README showcase, ARIS says the scores "are AI-review signals ([CSPaper]/[Stanford Agentic Reviewer]) … since ARIS optimizes *through* AI-review loops, high AI scores are an expected byproduct". Expect papers that look polished to an LLM reviewer (every critique pre-empted, clean claims-evidence mapping) while the experiments stay small.

## 2. Sakana AI Scientist v1 (SakanaAI/AI-Scientist)

Repo: https://github.com/SakanaAI/AI-Scientist (HEAD `1de1dbc`). It works from fixed code templates and uses Aider for code and writing.

**Research process**
- Templates (`templates/`): `nanoGPT`, `nanoGPT_lite`, `2d_diffusion`, `grokking`, `mobilenetV3`, `sketch_rnn`, `seir`, `MACE`, `earthquake-prediction`, `tensorf`, `probes`. `templates/nanoGPT/prompt.json`: "trains multiple small language models on multiple datasets of text at the character level" (shakespeare_char, enwik8, text8). In `templates/nanoGPT/experiment.py`: `num_seeds = {"shakespeare_char": 3, "enwik8": 1, "text8": 1}`; `torch.manual_seed(1337 + seed_offset)`; comment "we expect to overfit on this small dataset". Grokking uses `["x_div_y", "x_minus_y", "x_plus_y", "permutation"]` with 3 seeds each. The 2D diffusion datasets are circle, dino, line, moons.
- Ideas (`ai_scientist/generate_ideas.py`): "Come up with the next impactful and creative idea … you can feasibly investigate with the code provided. Note that you will not have access to any additional resources or datasets." The model rates itself on "Interestingness", "Feasibility" and "Novelty" from 1 to 10. Novelty check: "You will be given access to the Semantic Scholar API … top 10 results … Decide a paper idea is novel if after sufficient searching, you have not found a paper that significantly overlaps."
- Experiments (`perform_experiments.py`): `MAX_ITERS = 4`, `MAX_RUNS = 5`. "You are given a total of up to {max_runs} runs"; "we already provide the vanilla baseline results, so you do not need to re-run it". → A paper has at most 5 runs plus the baseline, and they are usually a hyperparameter sweep ("if you are sweeping over a specific hyperparameter, plan each value … for each run").
- Plotting: "modify `plot.py` … fill in the "labels" dictionary". Run directories `run_0 … run_5` are labelled one per curve, and figure filenames like `val_loss_enwik8.png` come straight from the template.

**Writing** (`ai_scientist/perform_writeup.py`)
- Fixed section order (LaTeX template `templates/*/latex/template.tex`): Introduction, Related Work, Background, Method, Experimental Setup, Results, Conclusions and Future Work.
- `per_section_tips` Abstract: "TL;DR of the paper - What are we trying to do and why is it relevant? - Why is this hard? - How do we solve it (i.e. our contribution!) - How do we verify that we solved it". → Abstracts go motivation → "This is challenging due to…" → "We propose a novel…" → "Our experiments … demonstrate". All 10 example papers in `example_papers/` follow this pattern.
- Introduction tip: "New trend: specifically list your contributions as bullet points"; "Extra space? Future work!".
- Background: "Usually includes a subsection, Problem Setting, which formally introduces the problem setting and notation". → A "Problem Setting" subsection is a v1 signature.
- Results: "Includes statements on hyperparameters and other potential issues of fairness"; "Discusses limitations of the method." → Limitations sit at the end of Results, not in their own section.
- Experimental Setup: "Do not imagine unknown hardware details." → Often no hardware or compute is reported.
- Source-level fingerprint: "Before every paragraph, please include a brief description of what you plan to write in that paragraph in a comment." → **arXiv LaTeX source has a `% ...` planning comment before every paragraph.**
- Citations: "You will be given access to the Semantic Scholar API, only add citations that you have found using the API"; `num_cite_rounds=20`; BibTeX is taken from `papers[i]["citationStyles"]["bibtex"]`. → BibTeX keys follow Semantic Scholar's pattern (e.g., `Vaswani2017AttentionIA`: CamelCase author+year+initials of the first title words) and include S2 fields. The citation count is small: Beel et al. found "a median of five citations, most outdated (only five of 34 from 2020 or later)".
- Title prompt: "re-think the Title … try by creative with it". The example papers have colon titles with promotional verbs: "DualDiff: Enhancing Mode Capture in Low-Dimensional Diffusion Models via Dual-Expert Denoising", "Unlocking Grokking: A Comparative Study of Weight Initialization Strategies in Transformer Models", "Grokking Accelerated: …", "StyleFusion: …", "Grokking Through Compression: Unveiling Sudden Generalization via Minimal Description Length".
- Template watermark: `template.tex` ends with "This work was generated by \textsc{The AI Scientist} \citep{lu2024aiscientist}.", and the PDFs carry an "AI-Scientist Generated Preprint" header. Both are easy to strip.
- Error list prompt: "Unescaped symbols, e.g. shakespeare_char should be shakespeare\\_char in text". → Code identifiers leak into prose (`shakespeare_char`, `MLPDenoiser`, `x_div_y`) as raw dataset or class names.
- Reviewer (`perform_review.py`): a NeurIPS-form JSON with Summary, Strengths, Weaknesses, Originality, Quality, …, Overall 1-10, Decision "Accept/Reject". The reviewer also produces "Limitations": "potential negative societal impacts".

## 3. Sakana AI Scientist v2 (SakanaAI/AI-Scientist-v2)

Repo: https://github.com/SakanaAI/AI-Scientist-v2 (HEAD `96bd516`). It is template-free and uses agentic best-first tree search (BFTS).

**Research process**
- `bfts_config.yaml`: `stage1_max_iters: 20`, `stage2_max_iters: 12`, `stage3_max_iters: 12`, `stage4_max_iters: 18`; `multi_seed_eval: num_seeds: 3`; `exec: timeout: 3600` (1 h per run); code model `claude-3-5-sonnet`, feedback and VLM model `gpt-4o`.
- Stage goals (`ai_scientist/treesearch/agent_manager.py`):
  1. "Focus on getting basic working implementation - Use a simple dataset"
  2. "Change hyperparameters … DO NOT change the model architecture … Introduce TWO more new datasets from HuggingFace"
  3. "Explore novel improvements … MAKE SURE you use THREE HuggingFace dataset in total"
  4. "Conduct systematic component analysis that reveals the contribution of each part".

  → **Exactly 3 small HuggingFace datasets, 3 seeds, a hyperparameter-tuning section, then an ablation section.** `parallel_agent.py` adds: "Make sure to create synthetic data if needed"; "This first experiment design should be relatively simple, without extensive hyper-parameter optimization"; "You MUST evaluate your solution on at least {num_syn_datasets} different synthetic datasets".
- Ideation (`perform_ideation_temp_free.py`): "propose high-impact research ideas resembling exciting grant proposals … Each proposal should stem from a simple and elegant question … Ensure that the proposal does not require resources beyond what an academic lab could afford"; "Title": "A catchy and informative title"; tool "SearchSemanticScholar". The idea also includes a "Risk Factors and Limitations" field.
- Workshop target: `ai_scientist/ideas/i_cant_believe_its_not_better.md` (ICBINB, "negative results, deep learning, failure modes").

**Writing** (`perform_icbinb_writeup.py`)
- System prompt: "publish a paper to the "I Can't Believe It's Not Better" (ICBINB) Workshop … highlight real-world pitfalls, challenges, and negative or inconclusive results"; "MINIMIZE THE USAGE OF ITEMIZE OR ENUMERATE"; Title "catchy and informative … under 2 lines"; Introduction: "Summarize your contributions or findings: they may include negative results, real-world pitfalls, unexpected behaviors, or partial improvements"; Method: "If results are not strictly an improvement, discuss partial successes or lessons learned"; Experiments: "Negative, unexpected, or inconclusive findings are valid contributions … Include up to 4 figures in the main text. All other figures should be in the appendix."; "suitable for a 4-page single-column workshop paper".
- Reflection prompt: "Can we use more information and details (hyperparameters, unused figures, etc.) in the supplementary material?"; the VLM figure review leads to "Be more aggressive with figure selection - move more figures to the appendix".
- The ICML variant (`perform_writeup.py`) has "Accurately report the experimental results, even if they are negative or inconclusive"; "If results are negative or inconclusive, highlight potential improvements or reasons and propose future directions"; and an Impact Statement page detector.
- Plot prompt (`parallel_agent.py`): "Use basic matplotlib without custom styles"; "Always include a title for each plot, and be sure to use clear subtitles—such as 'Left: Ground Truth, Right: Generated Samples'—while also specifying the type of dataset being used"; "descriptive names … include the dataset name and the type of plot". The aggregator prompt (`perform_plotting.py`) adds "no top and right spines, dpi of 300". → **Default matplotlib with an in-figure title on every panel ("Training Loss on <dataset>"), "Left: … Right: …" subtitles, and per-seed and aggregated variants of the same curve** (the prompt itself names `aggregated_training_accuracy.png` vs `per_seed_training_accuracy.png`).
- Template: `blank_icbinb_latex/template.tex` has Introduction, Related Work, Background, Method, Experimental Setup, Experiments, Conclusion, then `\section*{\LARGE Supplementary Material}`.

**Evidence from Sakana's own ICLR 2025 workshop submissions** (https://github.com/SakanaAI/AI-Scientist-ICLR2025-Workshop-Experiment, `sakana_review.pdf` per paper):
- Accepted paper title: "Compositional Regularization: Unexpected Obstacles in Enhancing Neural Network Generalization". Abstract: "**Contrary to our expectations**, our experiments on synthetic arithmetic expression datasets reveal that models trained with compositional regularization do not achieve significant improvements … These findings highlight the challenges …". This is the canonical form of a negative result reframed as a "pitfall" paper.
- Sakana team review of that paper: "does not cite Hochreiter and Schmidhuber (1997) but instead opts for the textbook by Goodfellow et al (2016)"; "The caption of Figure 3 is wrong"; "self-attention … performs significantly better than the LSTM version, while the text argues that they perform on par"; "sequence lengths are very short and the considered task is only synthetic"; code review: "about 57% of the test set overlapped with the training set"; "the main paper should use the notation e_t … instead of h_t" (the text describes a different tensor than the code uses).
- Label-noise paper: "the paragraph interpreting figure 3 refers to ECE measures, which are not displayed"; "the paper states that it compares different calibration methods, but the paper does not provide any results"; code review: "the AI Scientist had implemented temperature scaling … but never actually used it … the paper was influenced by these plans". → **Phantom experiments: methods from the plan described as if they had been run.**
- Pest-detection paper: "refers to domain adaptation being studied. The experiments … only investigate … data augmentation"; "Eurosat, Medmnist and CIFAR-10 results [unrelated] to the pest prediction problem"; "naming the multi-model-single-dataset experiment "multi-dataset"". Code review: the domain-adaptation code failed, so "the AI Scientist opted for an implementation that does not include this domain adaptation technique". → The title or section names keep the original intent while the experiments that actually ran are a fallback.
- The 2026 journal paper (arXiv 2606.15497, Yamada, Lange, Lu et al., "Towards End-to-End Automation of AI Research") lists the failure modes: "naive or underdeveloped ideas, incorrect implementations of the main idea, a lack of deep methodological rigor, errors in experimental implementation, duplicating figures in the main text and the appendix, and many types of hallucinations such as inaccurate citations."

## 4. Agent Laboratory (SamuelSchmidgall/AgentLaboratory)

Repo: https://github.com/SamuelSchmidgall/AgentLaboratory (HEAD `d9017d9`). Roles are PhD, Postdoc, ML engineer, SW engineer and professor. Literature review goes through the arXiv API. `mlesolver` handles code and `papersolver` the paper.

- Plan prompt (`agents.py`): "You should aim for a very simple experiment that showcases your plan, not a complex one … Your idea should be very innovative and unlike anything seen before."
- Data: "You MUST use a HuggingFace dataset in your code. DO NOT CREATE A MAIN FUNCTION. Try to make the code very simple." and "The submitted code must have a HuggingFace dataset import". → One HF dataset, usually small or subsampled.
- Paper (`papersolver.py`):
  - scaffold "Your paper should have the following sections: 1. Abstract 2. Introduction, 3. Background, 4. Related Work 5. Methods, 6. Experimental Setup 7. Results, and 8. Discussion … **Your title should start with Research Report: [title here]** … **For author write Agent Laboratory**." (line 509)
  - "The paper length should be 8 pages or 4000 words in total. It should be quite long and comprehensive. Remember, the paper MUST BE LONG." plus "you must increase this by {4000-paper_len} words." (lines 514, 543)
  - "You ABSOLUTELY must without fail also include Figure_1.png and Figure_2.png" (line 504)
  - citation "You can cite them just by putting the arxiv ID in parentheses, e.g. (arXiv 2308.11483v1)" (line 363)
  - "Use as many equations as you find necessary."
  - "Your goal was to write a research paper and get high scores from the reviewers" (line 565). The draft is scored by an LLM reward model, `get_score(...)`, and accepted edits must raise the score.
- Reviewers (`agents.py` lines 192-198): three personas, "harsh but fair … expect good experiments", "looking for an idea that would be impactful", "looking for novel ideas that have not been proposed before".
- → **Fingerprints:** a "Research Report:" title prefix; author "Agent Laboratory"; inline arXiv-ID citations "(arXiv 2308.11483v1)" with no proper bibliography; Background placed before Related Work and a Discussion section; exactly two figures named Figure_1/Figure_2 in Methods; prose padded to about 4000 words with many equations around a very simple experiment.
- Hidden-pitfalls study (Luo et al., arXiv 2509.08713): Agent Laboratory showed "82.4% preference for first-listed benchmarks regardless of difficulty", picked metrics by the order they were presented, and "generated undocumented synthetic datasets or subsampled provided data".

## 5. AI-Researcher (HKUDS)

Repo: https://github.com/HKUDS/AI-Researcher (HEAD `f9a6f84`). Paper agent: `paper_agent/*_composing.py`, using writing templates distilled from famous papers per domain (`paper_agent/{vq,gnn,diffu_flow,rec}/writing_templates/`, e.g. `neural_discrete_representation_learning_introduction_template.txt`, `maskgit…`, `sdxl…`).

- Introduction (`introduction_composing.py`): "RESEARCH BACKGROUND (2 paragraphs) … Present existing methods objectively, categorized in 1-3 research lines … Use citations extensively"; "RESEARCH MOTIVATION (1-2 paragraphs)"; "METHODOLOGY OVERVIEW (1-2 paragraphs) … This part should be long enough"; "CONTRIBUTIONS: Use \begin{itemize} … List 3-4 concrete contributions … Highlight novelty and significance … Include both methodological and empirical contributions".
- Experiments (`experiments_composing.py`) has a fixed hierarchy: "\section{Experiments} \subsection{Experimental Settings} \subsubsection{Datasets and Preprocessing} \subsubsection{Evaluation Metrics} \subsubsection{Baselines} \subsubsection{Implementation Details} \subsection{Main Performance Comparison} \subsection{Ablation Studies} …"; "Don't create subsections other than the above two types (e.g. … future work)". It also asks for LaTeX comments recording "Purpose and methodology of each experiment".
- Conclusion (`conclusion_composing.py`): "FUTURE WORK (only 1 sentence)"; "**Keep length to only 1 short paragraph**"; "Balance critique with optimism". There is **no Limitations section prompt**; "limitations" appears only as "limitations of existing methods".
- Abstract: "Keep to 150-250 words - Write as one cohesive paragraph".
- → **Fingerprints:** structure copied from classic papers (VQ-VAE, MaskGIT, LightGCN-style recsys); 3-4 itemized contributions; the exact four-subsubsection "Experimental Settings" block; a one-paragraph conclusion with a single future-work sentence and no limitations; domains limited to VQ, GNN, diffusion/flow and recommendation; possible leftover `%` purpose comments in the source.

## 6. CycleResearcher / DeepReviewer (zhu-minjun/Researcher)

Repo: https://github.com/zhu-minjun/Researcher (HEAD `8c1b253`). These are fine-tuned policy models trained on ICLR-style papers (Research-14k) and reviews (Review-5k), and they write the full paper from a reference list.

## 7. data-to-paper (Technion-Kishony-lab)

Repo: https://github.com/Technion-Kishony-lab/data-to-paper (HEAD `81df14c`). It performs hypothesis-testing research on a provided dataset, mostly biomedical and social science, with strong traceability built in.

- Writing order (`research_types/hypothesis_testing/writing_steps.py`): "Abstract, Introduction, Results, Discussion, and Methods" (Nature style). No subsections: "Do not include subsections". The Title "should … not include punctuation marks, such as ":,;" characters". Abstract must include "statement of limitations and implications". Forbidden phrases in Results: "Limitations", "Future work", "In conclusions". Discussion structure: "Recap the subject … Recap our methodology … compare them to the results from prior literature … Discuss the limitations of the study. End with a concluding paragraph".
- Numbers: "All numeric values … should be written with a proper \\hyperlink to its source"; the toy example is `\hyperlink{Z1a}{0.65}`; derived values come from `\num{exp(\hyperlink{Z3a}{0.17})}`. → **Every number in the PDF is a hyperlink to code output**, and colon-free titles. This is the opposite style to Sakana's, and very distinctive.
- Not an ML-paper pipeline. It matters mainly for applied or medical AI venues.

## 8. DeepScientist (ResearAI/DeepScientist)

Repo: https://github.com/ResearAI/DeepScientist (HEAD `b366244`, 2026-06-28). A long-horizon "find a SOTA-beating improvement" system with skills `idea`, `baseline`, `experiment`, `analysis-campaign`, `paper-outline`, `write`, `review`, `rebuttal`, and `nature-polishing`.

## 9. Karpathy autoresearch (karpathy/autoresearch, March 2026)

Repo: https://github.com/karpathy/autoresearch (HEAD `228791f`, 2026-03-25). It has no paper writing. It is an overnight hill-climbing loop that many 2026 papers and blog-style "agent did research" reports build on.

- `program.md`: "The training script runs for a **fixed time budget of 5 minutes**"; "**The goal is simple: get the lowest val_bpb.**"; "If val_bpb improved (lower), you "advance" the branch … If val_bpb is equal or worse, you git reset"; "LOOP FOREVER"; "**NEVER STOP** … The human might be asleep"; "approx 12/hour, for a total of about 100 over the duration of the average human sleep"; "A 0.001 val_bpb improvement that adds 20 lines of hacky code? Probably not worth it."
- `prepare.py`: `TIME_BUDGET = 300`, `MAX_SEQ_LEN = 2048`, `VOCAB_SIZE = 8192`, data `karpathy/climbmix-400b-shuffle`; the model is a single-GPU nanochat derivative (Muon + AdamW, about 50M params, depth 8).
- → **Fingerprints in derived papers:** val_bpb as the headline metric; "5-minute training budget" or fixed wall-clock budgets; a ~50M-parameter GPT with vocab 8192 on climbmix or FineWeb; results tables shaped like `results.tsv` (commit, val_bpb, memory, keep/discard, description); single-seed greedy accept/reject with gains of 0.001-0.01 bpb; a "progress.png"-style staircase plot of best-so-far against experiment index. Selecting on the validation metric with no held-out test set is post-hoc selection bias by design.

### Notes for building the screening skill
1. **Version-aware ARIS signals.** ARIS papers from before 2026-08-26 should look defensive and confessional (#16-18). From September 2026 they should look like confident "launch" papers with a 2-4 item Limitations block and "tradeoff" framing (#19-20). Do not treat either style alone as diagnostic. Combine it with #14, #15, #11, #12.
2. **Highest-yield combinations:**
   - #14 (diagnostic or negative reframing) + leftover method skeleton + #11/#12 (toy scale, 3 seeds, 3 small datasets) + #15 (reviewer-proofing).
   - #26/#27/#28 (phantom experiments, self-contradiction, intent-versus-execution mismatch). These are the clearest signals of low human oversight. Humans make such errors too, but rarely several at once.
   - Source-level artifacts #1-#4, #37 (watermarks, `%` paragraph plans, S2 keys, arXiv-ID citations, hyperlinked numbers).
3. **Ask for traces.** Luo et al. show auditing from the paper alone is near chance (55%) but rises to 82% with logs and code. A screening skill should note when code and logs are missing and recommend requesting them.
4. **Good human-led work that uses AI** typically shows human-chosen problems and datasets with clear motivation, scale matched to the claims, no phantom or contradictory results, and a coherent framing that does not drift. It may still show surface fingerprints #5, #7, #9, #10, #19, #23, because people run the same writing skills.
